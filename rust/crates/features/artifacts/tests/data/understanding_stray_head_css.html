3 验收

  • 审阅人 选了「完整审阅」或「重点审阅」时：本会话登记一张待发卡片，内含英文评论正文，每条意见写明文件和行号，结尾写明有没有阻塞合并的问题；审阅人 点击前 PR 上没有任何新内容。
  • 审阅没有阻塞问题时：交付附上 PR 的审阅页链接，审阅人 认可的话可以在 GitHub 上自己点 Approve。
  • 审阅人 选了「转交」时：本会话登记一张待发卡片，内含以 审阅人 名义的留言，写明接手人和理由；审阅人 点击前 PR 上没有任何新内容。
  • 审阅人 选了「不处理」时：本会话不起草任何文字，把“审阅人 决定不处理”发给发起本会话的每日巡检会话，然后结束。
  • 任何选项下：example-repo 仓库和 PR 状态不变（不提交、不推送、不改 PR 状态）。

2 审阅用什么形式发出？

  • 「一条评论」：卡片发出一条 PR 评论，结论和逐条意见都在正文里，每条意见带文件:行号。PR 上没有审阅状态，除非 审阅人 发出后自己在 GitHub 上点 Approve。今天就能交付。
    example-usercommented· “… No blocking issues found.”（结论按实际发现写）
  • 「先扩展待发卡片」：先给 CharlieBot 的待发卡片加上“PR 审阅”一类（审阅状态 + 挂在代码行上的行内评论），再发本审阅。作者拿到标准的 GitHub 审阅；本审阅要等那份 CharlieBot 改动做完并上线，它的方案另请 审阅人 批。
    example-userApproved或Changes requested· 正文 + 行内评论

推荐：「一条评论」。main 不要求批准，审阅状态不改变 PR 能否合并；带文件:行号的正文让作者逐条定位。

代价：意见不挂在代码行上，作者按行号自己找；PR 列表上没有绿色勾，除非 审阅人 自己点 Approve。

完整说明：为什么待发卡片只能发评论
  • CharlieBot 的待发卡片（charliebot github draft）只登记两类内容：新建 PR，或在 PR/issue 讨论区发一条评论。它没有审阅状态字段，也没有文件和行号字段。来源：charlie-bot rust/crates/github/src/target.rs
  • 所以 Approve、Request changes 和行内评论都发不出去。审阅人 自己在 GitHub 上点 Approve 不经过卡片，随时可做。
  • 「先扩展待发卡片」是 CharlieBot 仓库里的一项新功能，要另走一份方案、实现、审查和上线；它对以后所有以 审阅人 名义的 PR 审阅都有用，但本 PR 要多等这一轮。
