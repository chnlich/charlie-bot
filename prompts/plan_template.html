1 Problem

The CLI has a write path for delayed triggers through charliebot schedule-trigger, but the unified CLI command map has no trigger-listing subcommand. Sources: src/cli/main.py:19, src/cli/main.py:22

TriggerManager persists scheduled triggers as JSON files under the session's triggers directory. Sources: src/core/triggers.py:337, src/core/triggers.py:677, src/core/triggers.py:683

That makes it easy to double-schedule a watch, or to forget that a wake-up is already pending for a long-running job.

2 Solution

Add a read-only charliebot triggers list subcommand that loads the session's trigger JSON files and prints one row per trigger. No new state: the trigger files stay the single source of truth; the command only formats them. Current storage source: src/core/triggers.py:683

sessions/{id}/triggers/*.json→ triggers list→ one row per trigger

4 Forks

1 Scope: list triggers for the current session only, or across all sessions?

Recommendation: current session only, matching the cwd-derived session identity of the other CLIs.

Tradeoff: consistent with the rest of the CLI, but triggers created from other sessions stay invisible.

2 States: show pending triggers only, or all states including fired and expired?

Recommendation: pending only — the question this command answers is "what will wake me up".

Tradeoff: a tighter default, at the cost of history when debugging a trigger that already fired.

Resolved: all states (user reply "2 all").
